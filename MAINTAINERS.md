# Maintainers

ContextLease currently uses a lightweight maintainer model suitable for an
early-stage open-source library.

## Current maintainers

| Maintainer | Role |
|---|---|
| [@yuexiongHNU](https://github.com/yuexiongHNU) | Lead maintainer and release owner |

## Decision and review model

- Changes enter `main` through pull requests.
- At least one maintainer approval and all required checks are expected before
  merge.
- Schema, native ABI, algorithm identifiers, security posture, and release
  changes require an explicit compatibility note in the pull request.
- Routine decisions use lazy consensus. If maintainers disagree, the change
  remains unmerged until the compatibility and user impact are documented.
- Security and conduct reports are handled privately.

## Becoming a maintainer

Maintainers may nominate a contributor who has demonstrated sustained,
constructive participation; sound review judgment; and care for compatibility,
tests, documentation, and community conduct. Maintainer access is never granted
solely on commit count.

This file records project roles, not employment or copyright ownership.
