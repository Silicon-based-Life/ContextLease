值得保留的设计

核心抽象已具备差异化，不需要推倒重来。

宿主初始化模块

模块语义、固定/可变内容、模型和 Provider 由外部系统定义，符合通用框架边界。

Lease 必须可回收

借用额度前强制注册 reclaim pipeline，把借用从“临时超配”升级为可验证生命周期。

请求内事务

下一次 prepare 重算租约，没有后台线程修改已生成上下文，行为更易复现。

Pinned 保护

fixed/pinned 内容不进入压缩管线，超额时明确 admission failure。

Provider 解耦

Rust 两阶段协议让宿主调用模型，core 只验证语义候选和硬预算。

隐私默认安全

Python Debug Web 发布计数、ID、策略和哈希，prompt body 默认不进入遥测。

P0 · 发布阻断项

这些问题会让同一配置在不同语言中产生不同解释，必须先于功能扩展处理。

P0-1

Schema、Python enum、Rust DTO 是三份不同契约

Schema 声明的 static / priority / semantic_pipeline / tool_schema / hybrid 均会在 Python loader 中失败；Rust DTO 没有 lifecycle、allocation、reclaim、render_target、count_mode 等字段，并会静默忽略它们。

  • 实测 Rust 对 fixed/weighted/priority/elastic 得到同一 layout hash 和同一分配。
  • CLI validate 不运行 JSON Schema，Schema 禁止的未知字段仍被接受。
  • 方案：单一版本化 contract → 生成 DTO/enum → deny unknown fields → 跨语言 schema corpus。

P0-2

“Rust canonical core”目前只是可选路径

Python 默认导出的 ContextLeaseArena 是完整纯 Python 实现，NativeArena 是单独 opt-in。Python 有 14 个算法，Rust 只有 4 个确定性文本算法和 2 个语义请求类型；wheel 不含 native library。

  • 推荐：高层 Python API 默认委托 Rust；纯 Python 改为 reference/fallback。
  • 发布 platform wheels，避免安装后再手工设置 DLL 路径。
  • 如暂不迁移，README 必须明确 native 是功能受限子集。
P0-3

版本、默认分支和 release 尚未闭环

包/Cargo/C# 是 0.2.0，CLI 仍报告 0.1.0；metadata 校验脚本没有发现它。本地远端跟踪快照显示完整多语言实现仍在 agent 分支，默认 main 停在更早提交。

  • 统一版本源并端到端检查 CLI、ABI、NuGet、archive、badge。
  • 合入 main、通过 branch protection 后再打 prerelease tag。
  • 2026-07-21 经认证核验仓库仍为 private；独立开源发布前必须切换为 public。

P1 · 可信通用框架能力

解决后，ContextLease 才能在 C++、Go、Rust、Python、C# 中提供真正一致的上下文控制。

P1-1

让公开策略字段真正改变行为

当前 Python allocator 固定走 weighted fill；allocation/lifecycle/reclaim/render_target/admission_policy 没有控制对应语义，change_rate 也未参与决策。

  • 为 fixed、weighted、priority、adaptive、external 写出行为表和 golden tests。
  • adaptive 使用 EWMA/分位数需求、lease TTL、回收代价、冷却与滞回，避免抖动。
  • 未实现的字段先标记 reserved，不要进入稳定 contract。
P1-2

真实 tokenizer 与实际用量校准

Rust 把 tiktoken_* 仍按字符估算，C ABI 没有 token callback。所谓 exact/hybrid/calibrated 目前无法在多语言路径兑现。

  • ABI v2 支持 host count callback，或接收带 tokenizer fingerprint 的 measured_tokens。
  • 分别统计 text/messages/tools 及 provider render overhead。
  • 根据模型返回的 actual input usage 在线校准，并设置硬边界安全余量。
P1-3

从扁平字符串升级到 PreparedContextPlan

当前 Python/Rust 都把内容 JSON 化后用空行拼接，无法忠实表达 role、tool call、tool schema、dependency group 和 provenance。

  • core 返回 typed modules/chunks/messages/tools 和 compression decisions。
  • host renderer 负责 OpenAI、Anthropic 或私有协议序列化。
  • core 对 canonical rendered request 做最后 token 校验。
P1-4

强化语义压缩合同

substring required terms + 单调长度不足以保护事实、否定词、限定条件、引用和工具协议。

  • 增加 required facts、JSON Pointer、实体 ID、消息依赖组。
  • 记录 source hash、provider/model/prompt version、成本、延迟和尝试。
  • 加入缓存、deadline、cancel、费用上限，以及并行 portfolio 与可插拔选择器。
P1-5

跨语言 conformance 要比较完整结果

Python 58/58、Rust 6/6 通过，但共享 fixture 只有一个，断言仅覆盖 token 上限、必含词和一个 lease borrower，无法发现本次看到的契约漂移。

  • 20+ canonical fixtures 覆盖策略、算法、错误码、Unicode 和边界。
  • Python reference ↔ Rust full golden；所有 binding 在三平台复用。
  • property/fuzz/benchmark 成为 CI gate。
P1-6

把可观测性下沉到 native core

Python Debug Web 做得不错，但 Rust PreparedContext 没有 event/snapshot API，其他语言无法直接获得同一实时视图。

  • 增加 content-free snapshot/events pull API 或 host event callback。
  • 独立提供 Debug Web、OTLP、Prometheus exporter。
  • Debug Web 保持只读视图，不成为策略的唯一控制平面。

P2 · 生态、性能与供应链

降低真实项目采用成本，并为生产使用建立护栏。

P2-1

标准生态安装应直接可运行

Python wheel 不含 native；NuGet 不含 RID native assets；Go 需要固定目录的动态库；CMake 只有 smoke 工程。

  • 发布 platform wheels、带 runtimes 资产的 NuGet、CMake config/pkg-config。
  • 提供 vcpkg/Conan recipe 与稳定 Go module/tag/下载工具。
P2-2

为性能设硬门槛

similarity dedupe 可能 O(n²)，portfolio 串行调用，JSON FFI 多次复制，Python 单 arena 也会串行 prepare。

  • 先建立规模、并发、结构化内容 benchmark，再做 LSH、并行、批处理或 buffer API。
  • 对 P50/P95 latency、峰值内存、FFI copy 和吞吐建立回归阈值。
P2-3

补齐供应链与发布可信度

当前有 SHA256、ABI 版本和 panic containment，但缺少 SBOM、签名、provenance、ABI symbol snapshot 和安全扫描。

  • actions 固定 commit SHA，加入 CodeQL、cargo audit 和 Python dependency audit。
  • 发布 SBOM、Sigstore/cosign 签名与 SLSA provenance，并验证 ABI backward compatibility。
